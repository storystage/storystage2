# 2. Make it match the storyboard

A computing sequence in which the storyboard is the specification and StoryStage's check is the test. Learners write, predict, test and debug programs until the scene matches the plan.

| | |
|---|---|
| **Ages** | 7–9 (England Years 3–4, Scotland P4–P5, Wales steps 2–3, Northern Ireland P4–P5) |
| **Template** | 3-part (beginning, middle, end), so the focus stays on the code |
| **Time** | Three lessons of 45–60 minutes |
| **Groups** | Pairs, one device each |
| **Prompter** | Off is best: learners write every block. If used, Plan only: the Prompter helps with a plan in plain words, and learners build the blocks |
| **Curriculum** | `EN-CO-KS1-2`, `EN-CO-KS1-3`, `EN-CO-KS2-1`, `EN-CO-KS2-2`, `EN-CO-KS2-3`; `SC-TCH-1-13`, `SC-TCH-1-14`, `SC-TCH-1-15`, `SC-TCH-2-13`, `SC-TCH-2-14`, `SC-TCH-2-15`; `WA-ST-CO-2`, `WA-ST-CO-3`, `WA-DCF-PSM`, `WA-DCF-EVAL`; `NI-ICT-EXPLORE`, `NI-ICT-EVALUATE`, `NI-MA-KS1` |

## Learners will

- turn a storyboard frame into a precise sequence of instructions;
- predict what a program will do, then test the prediction;
- use a loop, and run two actions at the same time (do together);
- find and fix the difference between what they planned and what the program does.

## Before you start

- Make a short class production (three scenes, two characters each) with a finished storyboard but **no code**. Share the `.storystage` file with every pair. Each pair codes the same storyboard, so the class can compare.
- Seed one deliberate bug in a version for Lesson 3 (a character turns the wrong way, or speaks before it arrives).

## Lesson 1: from frame to steps

1. Look at the first frame together. Ask: "What has to happen, in order, to get from the start of the scene to this picture?"
2. Pairs write the steps in plain words on paper (this is an algorithm).
3. Build the steps as blocks: **move**, **turn**, **say**. Predict, rehearse, compare.
4. Run **Check against the storyboard**. Read its plain-words report together ("The fox is facing left; the storyboard shows it facing right").

## Lesson 2: loops and together

1. Scene 2 has a character who hops three times. Ask pairs to do it with three blocks, then with **count 3 times**. Which is easier to change to five hops?
2. Scene 2 also has two characters arriving together. Show the difference between **do in order** and **do together**: predict first, then rehearse both.
3. Open the **text view**: the same program as text. Which lines are the loop?

## Lesson 3: bug hunt

1. Give pairs the bugged version. They predict, rehearse, run the check, find the bug and fix it, then explain in one sentence what was wrong.
2. Pairs plant a bug in their own scene 3 and swap with another pair.
3. Finish with the Screening room: the whole film against the storyboard.

## Support and stretch

- **Support:** the teacher writes the plain-words steps for scene 1; learners only build the blocks. Use the Tiles editor if dragging is hard; both editors work by keyboard.
- **Stretch:** use **if** (for example, the fox says "Got you!" only if it is close to the rabbit) or an event (when the rabbit is clicked, it jumps).

## What to look for

- The learner explains what each block does and predicts the result before running it.
- The learner uses the check's report to find the mismatch, and fixes it without starting again.
- The learner can say why a loop or "do together" was the right choice.
