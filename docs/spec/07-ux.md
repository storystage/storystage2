## 1. The three tabs

The shell is Direction A's "Global layout": a 64 px header with the logo, the production's title, the three mode tabs and, set apart, **Learn** and **Settings**; below it, the working area inside a 3 px amber frame. The current frame stays the same when the learner changes tab. The Screening room has no Prompter and no Backstage.

### 1.1 Screen sizes

The layout follows the **window's size**, never the device or platform, so a resized desktop window, an iPad in Stage Manager and a Chromebook all behave the same way. There are three size classes, chosen by window width:

| Size class | Window width | Drawn at | Typical devices |
|---|---|---|---|
| Laptop | 1440 px and up | 1536 × 864 | Windows laptops at 125% scaling (1920 × 1080 screens), MacBook Air (1440 × 900, 1470 × 956) |
| Chromebook | 1280–1439 px | 1366 × 768 (the handoff size) | the reference Chromebook; 1280 × 800 screens |
| iPad | 1024–1279 px | 1180 × 820, landscape | iPad (10th generation on); must still work at 1080 × 810 (9th generation) and 1024 × 768 |

Below 1024 px wide (iPad portrait, narrow windows) the studio shows a neutral note, full screen: "Turn your iPad sideways, or make the window wider." The learner's work is kept, and widening the window brings the studio straight back. There is no portrait layout in the first release ([0033](../decisions/0033-narrow-windows.md)).

Height is not a size class. The layouts are drawn for 768 px tall and up; extra height goes where the table below says.

The mock-ups are in `docs/design/direction-a/sizes/` (open `index.html`), with PNGs in `screenshots/sizes/`.

### 1.2 What changes at each size

Widths are in CSS pixels. "As drawn" means the handoff's 1366 × 768 value.

| Region | Laptop | Chromebook | iPad |
|---|---|---|---|
| Header | as drawn | as drawn | the wordmark folds to the logo mark; tab padding 12 px; a long production title is cut short with an ellipsis |
| Storyboard: Backstage | panel, 236 | panel, 236 | a 96 px rail of Cast, Props, Set and Backdrops (as on the Production stage); a section opens as a panel over the sketch library |
| Storyboard: sketch library, script pane | 132 and 290 | 132 and 290 | 132 and 290 |
| Storyboard: frame canvas | grows to fill the main area, keeping its shape, up to 1.4 × | as drawn, shrinking if the window is shorter | fills the main area, keeping its shape |
| Production stage: frame strip | scrolls sideways, keeping the current frame in view | same | same |
| Production stage: scene view | 248 px tall plus half of any extra window height | 248 | as laptop (274 at 820 tall) |
| Production stage: Blocks palette | 300 | 300 | 280 |
| Production stage: the Prompter | panel, 340 | panel, 340 | panel, 320 |
| Screening room: right column | 560 | 544 | 420 |
| Screening room: player | fills the left column, 16:9 | 768 × 432 | fills the left column, 16:9 |
| Settings: navigation | 236 | 236 | 200 |
| Settings: columns | 400, then two equal | 360, then two equal | 300, then two equal; the page scrolls |
| Dialogs (set-up, export, editor switch) | as drawn, centred | as drawn | as drawn (920 fits) |

At every size the learner can collapse Backstage and the Prompter to their rails (the 44 px button in each panel's title band), which gives the code area the room back.

### 1.3 Touch

iPads and many Chromebooks are touch-first, so at every size:

- hit targets are at least 44 × 44 px (Direction A's rule already);
- nothing depends on hover: every tooltip has a visible label or a tap-to-show tip (13c);
- every drag has a tap or keyboard alternative ("Move to…", Direction A's Tiles rule, applies to blocks, plan steps, sketches and running-order cards too);
- when the on-screen keyboard opens, the focused field and its mic button scroll into view; the script pane's "Type or say a line…" field moves above the keyboard.

### 1.4 The Code editor before the storyboard

A scene's Code editor stays closed until the scene has a heading and at least one frame, and the script has a logline and synopsis (10.8). In its place the Production stage shows what is left, as a checklist in plain words (Done or To do, each with an icon), and a **Go to the Storyboard** button. Rehearse is unavailable while the stage is empty. Mock-up: screen 02c in `sizes/`. A teacher can relax the rule for imported worlds (`storyboard.allowImportedWithoutStoryboard`, 15.3).

## 2. States

### 2.1 The shell

- **Mode:** Storyboard, Production stage or Screening room. Exactly one is current; the header's three tabs are a tab list.
- **Current frame:** kept when the mode changes. The header's sub-line names it ("Scene 2 · Frame 2.3").
- **Panels:** Backstage and the Prompter are open or collapsed to their rails. The choice is kept per mode, on the device. The Screening room has neither.
- **Learn and Settings** open over the current mode and close back to it. Settings is for adults; Learn is for everyone.
- **What the build allows** comes from the host interface (decision 0028): whether a Prompter transport exists, and the policy in force. The studio never checks which platform it is on.

### 2.2 Themes

The design system has **one set of tokens, named by role** (`stage-0`, `panel-2`, `chalk`, `amber`, `prompter`, `ok`, `flag` and the rest; Direction A's README lists them). Components use only tokens, never a colour value. A theme is a set of values for those tokens.

- **Dark** is the default theme and the one approved with Direction A.
- **Light** (decision 0032) was approved on 25 Oct 2026 ([0038](../decisions/0038-light-theme-approved.md)); its values are in the token files and the handoff README ("Colour, light theme").
- **Settings › Accessibility › Theme** offers Dark, Light, or Match this device (`prefers-color-scheme`). The default is Dark ([0037](../decisions/0037-theme-setting.md)).
- **Forced colours** (Windows contrast themes): the components give way to the system colours, keep their outlines and focus rings, and never hide state behind a background colour alone.
- **Reduced motion** (`prefers-reduced-motion`): no animated transitions in the shell. The 3D scene and the film still play.

### 2.3 Frame status

A frame moves through **Planned** (it has a storyboard frame), **Staged** (actors are placed), **Coded** (its program isn't empty), **Rehearsed** (played since its last change) and **Checked** (passes the automatic check, or its flags have been kept). **Look at** marks a frame with an open flag. Editing a frame's code moves it back to Coded. A status always shows its icon and its word, never colour alone (Direction A's status colours).

### 2.4 The Prompter panel

What the panel shows (from StoryStage 1 spec 04 §3, plus plan before change, 13.9):

| State | Shown | Controls |
|---|---|---|
| Not in this build | Nothing: no panel, no rail; the neutral note from 12b where the panel would be | none |
| Off for this class | The neutral note from 12a, "switched off by your school" | none |
| Not set up | "Ask an adult to set up the Prompter." | none for learners; adults see **Set up…** |
| Ready | "You asked" bubbles so far, or a greeting | Type or say a request |
| Listening, Transcribing | the mic's state, in words | Stop |
| Planning | "The Prompter is planning…" | Stop |
| Planned | The plan, and the pill **Nothing built yet** | Edit, reorder, add or delete steps; **Build these steps**; Stop; Undo this request |
| Building | Each step's blocks as they land, highlighted | Stop |
| Built | What changed, step by step | Undo this request |
| Limit reached | What happens now, in the class's words ("For today the Prompter can explain, but not plan.") | as the new level allows |
| Error, Offline | What happened and what to do next (`04-prompter.md`) | as listed there |

The class's level (decision 0034) decides which modes appear; a mode that the level leaves out is not shown at all, rather than shown and refused.

### 2.5 Notes, unavailable controls and saving

- **Neutral note** (Direction A component): for something switched off or not available here. It is never styled as an error.
- **Unavailable controls** say why, in a visible line or a tip, not only by looking grey (for example Rehearse on screen 02c, "Nothing on the stage yet").
- **Saving:** changes save themselves. The page says "All changes saved" when they have. The browser version shows a banner while work isn't saved to a file (8.4).

### 2.6 Where the design system lives

A new package, **`packages/ui`** (`@storystage/ui`, owned by S5), holds the tokens (as CSS custom properties and as TypeScript), the bundled fonts and icons (decision 0031), the components (12.3, on React Aria Components, Apache-2.0) and the strings helper. It depends on React and React Aria only, and on no other workspace package. `apps/studio`, `packages/blocks`, `packages/tiles`, the frame canvas in `packages/sketches` and the Screening room use it. It can't live in `apps/studio`, because nothing may depend on the studio. Workplan section 4 doesn't list it yet.

## 3. Words

The rules are `CLAUDE.md` rule 9 and Direction A's "Hard rules".

- **The learner's view:** "the cat", "your scene", "the move block". These words never appear on screen: AST, node, field, invocation, token, schema, API, and "edit" as a noun (a change is "a change", not "an edit"). "Edit" as a button that edits is fine.
- **Product terms, used exactly** (12.4): Storyboard, Production stage, Screening room, Backstage (Cast, Props, Set, Backdrops), Rehearse, Code editor (Blocks or Tiles), the Prompter, frame, shot, Export for distribution, Projection stage.
- **Steps are named after what changed:** "Add cat", "Make cat say Hello". These are also the undo labels (WP2.3).
- **Errors say what happened and what to do next,** with no apologies.
- **Style:** UK English; short and encouraging; no exclamation-mark overload.
- **Strings live in translation files** (12.4), never in components: one file per package and language, `src/strings/en-GB.json`, with keys named by place (`storyboard.shot.medium`). Text can carry named values (`{name}`); plurals use the language's plural rules (`Intl.PluralRules`). The first release ships English (UK) only; the files let Welsh, Scottish Gaelic or Irish follow after the pilot ([0036](../decisions/0036-languages.md)).

## 4. Accessibility

WCAG 2.2 AA throughout (rule 7), with these specifics:

- **Contrast:** text 4.5:1 (3:1 for large text); outlines and focus rings 3:1, in both themes. Status never by colour alone.
- **Focus:** every interactive element shows Direction A's focus ring, a 2 px gap in the surface's colour, then 3 px of amber (a dark-amber ring on light surfaces, a chalk ring on amber ones). Focus is never hidden under a panel or the on-screen keyboard (2.4.11).
- **Targets:** 44 × 44 px or larger, beyond the 24 px the standard asks (2.5.8).
- **Dragging:** every drag has a single-pointer and a keyboard alternative ("Move to…", arrow keys while focused) (2.5.7).
- **Keyboard paths:** every task in all three tabs can be done from the keyboard alone (the M4 manual test). Regions are landmarks: the header (banner), the mode tabs (tab list), the working area (main), Backstage, the script pane and the Prompter (complementary, each named). Keyboard shortcuts live in one keymap, avoid keys the browser reserves, and are listed under Learn. The keymap lands with the first shortcut: the shell needs none, because Tab and the arrow keys reach every part of it.
- **Screen readers:** each component has a role and an accessible name (React Aria provides most). Changes the learner didn't make themselves are announced in a polite live region: the Prompter's state, build and export progress, and the automatic check's results.
- **Speech:** captions for all speech, always (rule 7). Every mic button has a typed alternative beside it, except the key field, where speaking isn't offered at all.
- **Zoom and text size:** decision 0033 sets the working tabs' minimum at 1024 px wide. At 200% zoom a 1366 px window is only 683 px wide, so:
  - the three working tabs (the stage, the editors, the frame canvas) count as content that needs two-dimensional layout (the exception in 1.4.10), and below 1024 px they show 0033's note;
  - Settings, Learn, the set-up wizard and every dialog reflow down to 320 px and never show the note;
  - **Settings › Accessibility › Text size** (100%, 125%, 150%) scales the type tokens without narrowing the window, so a learner who needs bigger text keeps the studio.

  Decided by the owner ([0035](../decisions/0035-zoom-and-text-size.md)).

## 5. Tests

How each rule in this spec is tested, and at which level (`09-testing.md`).

- **Screen sizes (1.1, 1.2):** Playwright opens each tab at 1536 × 864, 1366 × 768 and 1180 × 820, checks that no region overflows its column, and compares a screenshot with the mock-up PNGs (WP12b, 12.5). axe runs at each size.
- **Touch (1.3):** an automated check that every interactive element is at least 44 × 44 px; a manual pass on the reference iPad and Chromebook (M4 manual test).
- **Storyboard first (1.4):** a component test that the Code editor stays closed until all three conditions hold, and opens when they do (WP10b).
- **Tokens and themes (2.2):** a unit test computes the contrast of every text, outline and focus-ring pairing the components use, in both themes, from the token values alone, with no browser. A component that uses a colour value instead of a token fails lint.
- **Components (2.4, 2.5, 4):** Vitest with a DOM (happy-dom) and Testing Library. Each component has tests for its role and name, its keyboard behaviour (Tab, Enter, Space, arrows where it has them), its focus ring, and its states.
- **Words (3):** a unit test reads every `en-GB.json` and fails on the banned words (with "Edit" allowed as a button label) and on keys a component uses that are missing.
- **Accessibility (4), end to end:** Playwright with axe (`@axe-core/playwright`, MPL-2.0, unmodified) on every screen, in both themes, at the three sizes: no serious or critical issues (12.5; WP12's done-when). A keyboard-only script per tab.
- **Manual (M4):** a screen-reader pass with NVDA on Windows and VoiceOver on the reference iPad, and a 200% zoom pass.
- **The Storyboard (6), unit:** the storyboard's edits (header, arc, cards, frames, sketches, lines, pins) as pure functions over the production, each leaving `checkReferences` clean, each with its undo label, and undo and redo restoring the production exactly; the arc template change keeping only matching parts; the limits in 6.9.
- **The Storyboard (6), components:** Add a scene unavailable until the logline and synopsis are written; reordering cards, frames and lines by keyboard; adding, moving, scaling, flipping, layering and removing a sketch by keyboard; pinning and unpinning a line.
- **The Production stage (7), components:** the Code editor closed until the scene is storyboarded; adding, moving, turning and resizing an object by keyboard, each one undo step; a palette block added by Enter, with the cascade; Rehearse unavailable on an empty stage; a code change stopping a rehearsal. The stage is the fake stage that records calls (WP0.8).
- **The Production stage (7), end to end:** milestone M2's gate in the browser (`docs/test/M2-one-scene.md`, automated where it can be): add models, place them, code the scene with blocks, Rehearse it; the same by keyboard alone; axe with the scene view, the Code editor, the cascade and Rehearse open.
- **The Storyboard (6), end to end:** a production planned end to end by keyboard alone (WP10's done-when, with the M4 manual test); axe on the Storyboard in both themes at the three sizes; the print layout's page count and contents for the example production.

## 6. The Storyboard (WP10a)

Direction A's screen 01, at the sizes in section 1. The data is `03-production-format.md` sections 3–6; this section is what the learner sees and does with it.

### 6.1 Layout

Left to right: **Backstage** (the Cast, Props, Set and Backdrops this production uses; the whole catalogue joins with 10.9), the **sketch library** (sketches of those items, then the storyboard marks and the backdrop sketches), the **main area** (script header, scene strip, frame tools, frame canvas) and the **script pane**. On iPad, Backstage folds to its rail (section 1.2). Each column is a named landmark (section 4).

Until Backstage's catalogue loads at run time (WP3c, S4), the sketch library offers the storyboard marks, the backdrop sketches and labelled stand-ins.

### 6.2 Script header (10.1)

- **Title**, **logline** (one sentence) and **synopsis** (a short paragraph), each a text field with its mic button once speech is in (WP14). The Prompter never writes them (rule 4).
- Until the logline and the synopsis both have words in them, **Add a scene** is unavailable and says why: "Write a logline and a synopsis first."
- A "3 scenes · 1 min 12 s" pill sums the scenes and the frames' planned lengths.

### 6.3 Arc (10.2)

- The learner picks **Free**, **3-part** (Beginning, Middle, End) or **5-part** (Setup, Conflict, Challenge, Climax, Resolution). Free has no parts.
- A template is an id, a name and its part names, in one list (`ARC_TEMPLATES`). A curriculum template (WP16) joins the list by id (`{ curriculum: '<id>' }` in the data), with no code change.
- Each scene card can belong to one part. Changing the template keeps a card's part only if the new template has a part of that name, and is one undo step ("Change arc to 5-part").

### 6.4 Scenes and frames (10.3)

- **Scene cards** show their number and heading (place and time, "Forest, night"), arc part, cast, transition (cut, fade to black, crossfade) and length. A card's heading is what 10.8's storyboard rule checks. The chosen scene's card is shown in full below the strip: its heading, part of the arc (or none), how it ends (the last scene's ending isn't used, and says so), its cast, and **Delete scene**. The cast is filled from Backstage (10.9).
- **Add a scene** adds a card, its code and its set-up as one step (`packages/production`, through a contract PR S4 reviews). **Delete** asks first, saying what goes with it (its frames, its lines and its code); it's one undo step.
- **Reorder** scenes by dragging a card's handle, or from the keyboard: focus the handle, Enter, the arrow keys, Enter. This reorders the running order (03 section 3). Frames reorder within their scene the same way.
- **Frames** sit under their card as numbered squares (2.1, 2.2). Choosing one makes it the current frame, which stays current across the three tabs. **Add a frame** adds one after the current frame. Deleting a frame with sketches or pinned lines asks first; its lines stay in the script, unpinned.
- "Most scenes need 3 to 9 frames" shows as a hint beside a scene with fewer or more. It never blocks anything.

### 6.5 Frame canvas (10.6)

- A white 16:9 frame with black-line sketches on it (decision 0014: no outside drawings), its caption, **shot** and **length** above it, and its pinned lines below it.
- **Shot:** Wide, Medium and Close-up in the segmented control (Direction A); Over the shoulder, Two shot and Follow under **More shots**. **Length:** a stepper from 1 to 30 seconds, 3 by default.
- **Adding a sketch:** drag it from the library (by the tile, or by its handle from the keyboard), or focus it and press Enter, which puts it in the middle of the frame, in front, and chooses it. Its facing and pose (front, three-quarter, side, back; standing, walking, pointing, sitting) are chosen in the library once Backstage's catalogue gives models their sketches (WP3c); marks, backdrop sketches and stand-ins have none. A frame holds up to 30 sketches; at 30 the library says so and adds no more.
- **The selected sketch** has an amber box with corner handles (edged in ink, so it shows on the white), and a toolbar of labelled buttons below the frame: **Flip**, **Bring forward**, **Send back**, **Bigger**, **Smaller** and **Remove**. Drag a sketch to move it; drag a corner handle to resize it.
- **Every drag has a keyboard way** (section 4), the same way as reordering scenes: pick up, move, put down. The sketches on a frame are a list, back to front, that the arrow keys move through ("Owl, on the left"); Home and End go to the ends. **Enter** (or Space) picks the focused sketch up; then the arrow keys move it 1% of the frame (10% with Shift), and + and − scale it by 10% (from 0.1 to 3 times), until **Enter**, Space or Esc puts it down, saying where it is. **Delete** removes the focused sketch. These keys work only while a sketch has focus (WCAG 2.1.4).
- Each change is one undo step, named for what changed: "Move owl", "Flip cat", "Remove key". One pick-up's moves are one step, as are one drag's; its resizes are another.

### 6.6 Script pane (10.4)

- **Script · Scene 2** lists the scene's lines in order. **Action** lines are paragraphs; **dialogue** lines carry the speaker's name in capitals, then the line.
- **Adding a line:** the "Type or say a line…" field (Enter or **Add line** adds it at the end of the scene), with **Who says it** above it: Action, the scene's cast, anyone already speaking in the script, or a name the learner types. Its list opens from its button or as the learner types, never just on focus. Who says it stays as it was for the next line.
- **Changing a line:** choosing a line opens it below the list, like the chosen scene card: its words, **Who says line 3**, and **Delete line** (one undo step, no question). Typing into a line is one undo step until the learner leaves it.
- **Pinning:** each line has a **Pin** button, showing the frame's number once pinned. It offers the current frame first ("Pin to frame 2.3, this frame"), then the scene's other frames, and **Unpin** when the line is pinned. With no frames in the scene the button is unavailable and the pane says to add one. Lines pinned to the current frame are highlighted, and show under the frame canvas. A line can be pinned to one frame; a frame can have several lines.
- Lines reorder by their handle, by drag and by keyboard, as cards do. A line holds up to 500 characters, a speaker's name 40, and the script 2,000 lines.
- **Fountain:** reading and writing follow 03 section 5, with its size limits, in `packages/production` (a contract PR S4 reviews). **Import a script** and **Export the script** appear when the host can open and save files (WP8.4). Importing is offered only while the production has no scenes yet: each heading becomes a scene, with its lines under it.

### 6.7 Print (10.7)

**Print storyboard**, beside Undo and Redo, opens a print layout in the device's print dialog, which also offers Save as PDF (decision 0054). The layout is in the page only while the dialog is open, and the app itself never prints. It is black on white in either theme, A4 landscape:

- the title, logline and synopsis;
- then each scene in running order: its number, heading and arc part, and its frames three to a row, each with its sketches, shot, length, caption and pinned lines, and a ruled line under it for the teacher's marks;
- the production's title and the page number at the foot of every page (CSS `@page` margin boxes).

A frame is never split across two pages. Where a device's web view can't print (to be checked in the desktop shells and on iPad), the host gives it a native print step, with the same layout.

### 6.8 Undo

The Storyboard keeps its own undo history: Ctrl+Z (Cmd+Z on a Mac and iPad) undoes, and Ctrl+Shift+Z (Cmd+Shift+Z) redoes. These are the first shortcuts in the keymap (section 4), and Learn lists them. In a text field they belong to the field, which undoes its own typing. **Undo** and **Redo** buttons above the script header do the same for touch and the mouse; each is named for the step it would undo ("Undo: Write logline"), and a screen reader hears what was undone. Typing into one field is one step until the learner leaves the field. Every step is named after what changed: "Write logline", "Add scene 3", "Move cat". When the production's undo arrives (WP8.2, S4), the Storyboard's steps join it, so one history covers the storyboard, the code and the set-ups.

### 6.9 Limits

| Field | Up to |
|---|---|
| Title | 80 characters |
| Logline | 200 characters |
| Synopsis | 1,000 characters |
| Scene heading | 80 characters |
| Caption | 200 characters |
| Script line | 500 characters |
| Speaker's name | 40 characters |
| Lines in the script | 2,000 |
| Scenes | 50 |
| Frames in a scene | 30 |
| Sketches on a frame | 30 |

Typing stops at the limit and the field says so ("200 characters at most"). A Fountain file over 03's limits isn't opened, and the learner is told why.

## 7. The Production stage (WP7)

The second tab: set the scene and code it (decision 0015: the Code editor is a view inside it). Direction A screen 02, with 02c for a scene not yet storyboarded (section 1.4) and 06 for setting the stage from a frame (WP10c). The editors themselves are in `14-editors.md`; this section is the screen around them.

### 7.1 Layout

- **The frame strip** across the top: every frame, grouped by scene (`FrameStrip`, 12.3), each with its sketch and its status (Planned, Staged, Coded, Rehearsed, Checked). Choosing a frame makes it current in all three tabs, and its scene the one shown below.
- Below it, left to right: **Backstage** as a 96 px rail of Cast, Props, Set and Backdrops, each opening as a panel over the scene view (searchable across all four, decision 0058); the **main column**; and **the Prompter** (WP13c, S7), which is absent when the host has none (decision 0022).
- The main column holds the **scene view** (section 7.2) above the **Code editor** (section 7.3). The scene view's title band shows the current frame's plan ("Frame 2.3 · sketch asks for a medium shot, 3 s"), **Camera view** and **Look around**, and **Rehearse**.
- Sizes follow section 1.2. Backstage and the Prompter collapse to their rails to give the Code editor room.
- The mock-up's "When frame 2.3 starts" heading over the code is drawn from WP10b's links, not from the program: the program has the scene's script method and its listeners (`01-ast.md` section 1), and a frame lists the blocks it links to (`03-production-format.md` section 7). WP10b shows those links as markers on the blocks; the code area's tabs are the methods (section 7.3).

### 7.2 Scene view (7.1)

- **What it shows:** the current scene's set-up on the stage (`@storystage/stage`). **Camera view** looks through the scene's camera, as the film will. **Look around** orbits a separate camera with the pointer, touch or arrow keys, and never changes the scene. "In this shot:" names what the scene's camera sees.
- **Adding:** drag a model from Backstage onto the stage, or focus it and press Enter, which puts it on the ground in front of the camera, facing it. A new object is a field in the scene's type and an entry in its set-up, as one undo step ("Add owl"), through the production's edits (`add_model`, WP8.2, S4).
- **Choosing an object:** click or tap it, or choose it in **Objects in this scene**, a list beside the view that is its keyboard path (as the sketches are on a frame, section 6.5). The chosen object has an amber outline and handles to move it along the ground (up and down with Shift), turn it and resize it, and a row of fields: x, y and z in metres, the turn in turns (Alice's unit, `02-story-api.md` section 1) and the size.
- **From the keyboard:** in the list, Enter picks the object up; then the arrow keys move it 10 cm (1 m with Shift), Page Up and Page Down raise and lower it, [ and ] turn it an eighth, + and − resize it by 10%, and Enter or Esc puts it down, saying where it is. One pick-up is one undo step, as one drag is.
- **Posing:** a character's **Pose** lists its joints from the joint map (WP3.3); each turns by fields or handles, within the joint's limits (decision 0051: joints turn only).
- **Camera and markers:** **Move the camera here** (from Look around) sets the scene's camera to the view, as one step; **Add a marker** puts a camera or object marker where the view is. Markers are objects in the list.
- **Removing:** **Remove** on the chosen object, which asks first when the code uses it, saying where, and is refused in plain words while code still needs it (as deleting a scene is, `03-production-format.md` section 2).
- **What the stage needs to add** (a contract request to S3, `00-architecture.md` section 6): the object at a point on the view (picking for editing, not only for running); an outline and handles drawn on the chosen object; a Look around camera that leaves the set-up alone; changing one object's transform or joint in the loaded set-up without reloading; and which objects the scene's camera sees.

### 7.3 Code editor (7.2, 7.6)

- **Closed until the scene is storyboarded** (section 1.4).
- **One method per tab:** the scene's script method first, then its listeners ("When the scene starts", "When the cat is clicked"), then the learner's procedures and functions. **New** adds a procedure, a function or an event listener to the scene or to a class of the learner's.
- **The palette** (300 px): an object picker (the scene, its camera, its objects, and the object a method belongs to), then that object's Actions and Questions in Alice's categories (`14-editors.md` section 2.1), and the control blocks: do in order, do together, count, while, for each, each in together, if, a variable, assign, comment and return.
- **Adding a block:** drag it into the method, or focus it in the palette and press Enter, which puts it after the statement with focus (or at the end of the method). Either way the shared cascade asks for the arguments that have no default ("Who moves? Which way? How far?"), and Esc cancels the drop (`14-editors.md` section 2.3).
- **Show as text** opens the read-only text view beside the code (`packages/text-view`, S6), Python-like or Java-like (7.6).
- **Blocks or Tiles:** the switch, its dialog (screen 05) and the class default are WP7t's (`14-editors.md` section 4).
- The Code editor loads on demand, in its own chunk, so the Storyboard opens without Blockly.

### 7.4 Rehearse (7.4)

- **Rehearse** plays the current scene live in the scene view from its set-up, with WP6.4's controls: pause and play, restart, speed (half, normal, double), **Rehearse to here** on a block (fast-forward to it), and **Stop**, which always works (6.3).
- The block running is highlighted (`highlight(nodes, 'rehearse')`). An error stops the run, explains itself in plain words beside the block, and highlights it (`'error'`).
- Rehearse never changes the set-up: Stop puts the scene back as it was. Changing the code during a rehearsal stops it first and says so in the live region.
- Rehearse is unavailable while the stage is empty or the Code editor is closed (section 1.4). A run that the frame's checks accept marks the frame Rehearsed (WP11.6 marks it Checked).

### 7.5 Undo (7.3)

The scene view and the Code editor share one history, which joins the production's own undo when it arrives (WP8.2, S4), as the Storyboard's does (section 6.8). Each step is named for what changed ("Add owl", "Move cat", "Make cat say Hello"). Ctrl+Z and Ctrl+Shift+Z (Cmd on a Mac or iPad) undo and redo outside text fields, and **Undo** and **Redo** buttons do the same. A step made in one editor undoes in the other after a switch (`14-editors.md` section 4). "Project history" is the production's saved versions, WP8.2's.

### 7.6 Keyboard and names (7.5)

- Landmarks: Backstage and the Prompter (complementary, named), the scene view and the Code editor (regions, named), the frame strip (a list).
- Every control in this section has a keyboard path, given above; every drag has a keyboard and a single-pointer way (section 4). The editors' own paths are in `14-editors.md` sections 3d (Tiles) and 3i (Blocks).
- Changes the learner didn't make (the Prompter's builds, a rehearsal stopping, an error) are announced in the polite live region.

### 8.2 A starting lock for a class

What the teacher's guide suggests a pilot school sets first, in the policy file's format (spec 05 §3.5). Some lines only say the default out loud, so the school can see it; nothing here turns anything on for a learner, and the Prompter stays off until an adult adds a key (0022).

```
prompter.enabled=true
prompter.dailyCap=20
prompter.capAction=explainOnly
backstage.import=teacher
backstage.search=false
editor.locked=false
update.channel=pilot
```

A pilot school is on the `pilot` channel (spec 05 §4.4); other schools use `stable`. During a term, add `update.pin=<version>` to hold the class on one build. For an exam or an unsupervised room, `prompter.enabled=false`.

### 8.4 Questions for the pilot teacher

- **Adding 30 names one at a time is slow.** Would pasting a list, or reading a CSV from the school's system, help? (The target is a class set up in under 15 minutes.)
- **Teacher-only screens have no password.** The bin, promoting a pupil's model and the usage view are behind Settings, on the trust model of the name picker (PS1). Is that enough in a classroom, or does the teacher need a PIN?
- **Ending the lesson:** should the folder close when the app closes, after a time with nothing done, or only when the teacher says so?
- **Marking:** marks go on the printed storyboard or into the school's own system. StoryStage has no teacher comments inside a production. Is that a gap?
- **The same device each lesson:** if pupils rarely get it, Collect and Hand back become every lesson's routine, and the guide should say so first.
