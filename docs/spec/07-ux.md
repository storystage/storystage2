## 1. The three tabs

The shell is Direction A's "Global layout": a 64 px header with the logo, the production's title, the three mode tabs and, set apart, **Learn** and **Settings**; below it, the working area inside a 3 px amber frame. The current frame stays the same when the learner changes tab. The Screening room has no Prompter and no Backstage.

### 1.1 Screen sizes

The layout follows the **window's size**, never the device or platform, so a resized desktop window, an iPad in Stage Manager and a Chromebook all behave the same way. There are three size classes, chosen by window width:

| Size class | Window width | Drawn at | Typical devices |
|---|---|---|---|
| Laptop | 1440 px and up | 1536 × 864 | Windows laptops at 125% scaling (1920 × 1080 screens), MacBook Air (1440 × 900, 1470 × 956) |
| Chromebook | 1280–1439 px | 1366 × 768 (the handoff size) | the reference Chromebook; 1280 × 800 screens |
| iPad | 1024–1279 px | 1180 × 820, landscape | iPad (10th generation on); must still work at 1080 × 810 (9th generation) and 1024 × 768 |

Below 1024 px wide (iPad portrait, narrow windows) the studio shows a neutral note, full screen: "Turn your iPad sideways, or make the window wider." The learner's work is kept, and widening the window brings the studio straight back. There is no portrait layout in the first release ([0033](../decisions/0033-narrow-windows.md)).

Height is not a size class. The layouts are drawn for 768 px tall and up; extra height goes where the table below says.

The mock-ups are in `docs/design/direction-a/sizes/` (open `index.html`), with PNGs in `screenshots/sizes/`.

### 1.2 What changes at each size

Widths are in CSS pixels. "As drawn" means the handoff's 1366 × 768 value.

| Region | Laptop | Chromebook | iPad |

| Storyboard: sketch library, script pane | 132 and 290 | 132 and 290 | 132 and 290 |
| Storyboard: frame canvas | grows to fill the main area, keeping its shape, up to 1.4 × | as drawn, shrinking if the window is shorter | fills the main area, keeping its shape |
| Production stage: frame strip | scrolls sideways, keeping the current frame in view | same | same |
| Production stage: scene view | 248 px tall plus half of any extra window height | 248 | as laptop (274 at 820 tall) |
| Production stage: Blocks palette | 300 | 300 | 280 |
| Production stage: the Prompter | panel, 340 | panel, 340 | panel, 320 |
| Screening room: right column | 560 | 544 | 420 |
| Screening room: player | fills the left column, 16:9 | 768 × 432 | fills the left column, 16:9 |

At every size the learner can collapse Backstage and the Prompter to their rails (the 44 px button in each panel's title band), which gives the code area the room back.

### 1.3 Touch

iPads and many Chromebooks are touch-first, so at every size:

- hit targets are at least 44 × 44 px (Direction A's rule already);
- nothing depends on hover: every tooltip has a visible label or a tap-to-show tip (13c);
- every drag has a tap or keyboard alternative ("Move to…", Direction A's Tiles rule, applies to blocks, plan steps, sketches and running-order cards too);
- when the on-screen keyboard opens, the focused field and its mic button scroll into view; the script pane's "Type or say a line…" field moves above the keyboard.

### 1.4 The Code editor before the storyboard

A scene's Code editor stays closed until the scene has a heading and at least one frame, and the script has a logline and synopsis (10.8). In its place the Production stage shows what is left, as a checklist in plain words (Done or To do, each with an icon), and a **Go to the Storyboard** button. Rehearse is unavailable while the stage is empty. Mock-up: screen 02c in `sizes/`. A teacher can relax the rule for imported worlds (`storyboard.allowImportedWithoutStoryboard`, 15.3).

As built (18 Nov): with that switch on, a production whose `manifest.origin` is `alice` (an imported Alice world, spec 19) opens its Code editor and Rehearse whatever its storyboard has, with no checklist. A production made in StoryStage keeps the rule, whatever the switch. The switch is off in the browser version.

## 2. States

### 2.1 The shell

- **Mode:** Storyboard, Production stage or Screening room. Exactly one is current; the header's three tabs are a tab list.
- **Current frame:** kept when the mode changes. The header's sub-line names it ("Scene 2 · Frame 2.3").
- **Panels:** Backstage and the Prompter are open or collapsed to their rails. The choice is kept per mode, on the device. The Screening room has neither.
- **Learn and Settings** open over the current mode and close back to it. Settings is for adults; Learn is for everyone.
- **An export** goes on while the learner works in another mode (spec 08, section 4; "Keep working"). The Screening room's tab carries a badge in its corner while it runs ("64%"), when it's made but not saved ("Save"), or when it stopped ("!"). The badge takes no width, so the header's tabs stay on one line at 1180 px, and a screen reader hears it with the tab's name ("Screening room, exporting 64%"). Choosing the tab then opens the export's dialog. A saved export leaves no badge.
- **What the build allows** comes from the host interface (decision 0028): whether a Prompter transport exists, and the policy in force. The studio never checks which platform it is on.

**The study session, as built (17 Nov; spec 14 sections 6.2, 6.3 and 6.6; WP7.13):** while study mode is on.
- **When a session runs:** for a pupil the teacher ticked, from their folder opening to its closing.
- **With no class list:** as a film opens, the studio asks the adult **Is this learner taking part in the study?**
  - **No** comes first, with focus, and closing the question counts as No.
  - The answer lasts until StoryStage closes.
- **The study bar:** the working area's first row, inside the amber frame, so the mode tab stays joined to it, and apart from the notices. It's a region named "Study" showing "Study session K7P3-QX2M".
- **What the session is told:**
  - each step the history closes: a run of typing is one step, counted once it closes;
  - each undo and redo;
  - the learner's own switch of editor;
  - Learn opened, as help.
  The session keeps only what its phase allows: outside a task, only switches. A session with neither a task nor a switch keeps no log.
- **Study tasks, as built (17 Nov; spec 14 sections 6.4 and 6.5, on S6's tasks, #494):**
  - **The list:** **Study tasks** in the bar lists the five tasks, each with **Start**. A task done in this session is ticked "Done" and can't start again.
  - **Starting a task:** the learner's own film is saved, then set aside with its history. The task's prepared film opens in memory only on the Production stage, and the title shows the task, with no Film menu. Saving waits until the task ends, and nothing of the task is kept.
  - **The task card** takes the Prompter's place on the right, in the studio's colours, a region named "Study task: Say hello". It has:
    - the instruction;
    - **Read it to me**, with an on-device voice, shown only when there is one, and stopped when the card closes;
    - **Hint**, which shows the hint and counts as help;
    - **Check my step**;
    - **Stop this task**.
  - **Check my step** plays the scene on a hidden stage through the check's `traceScene`, with the task's events. It then tests the task's end state. A success ends the task with "You did it!". Otherwise the card says "Not quite yet. Rehearse it and watch what happens.", or an error's own words. The last run of typing counts before the check and before the end.
  - **The time limit:** after fifteen minutes the task ends with "Time's up for this task. Well done for trying."
  - **Holding the editor:** T1 to T3 hold the class's default editor through the switch's lock, with "Set to Blocks for this study task". Only what's shown is held, so the learner's own choice isn't logged as a switch. The Prompter is held off while a task is open.
  - **After every task:** the learner's own film comes back as they left it, then **Two quick questions** asks "How easy was that?" (Hard, OK, Easy, Skip) and "Which way of coding would you choose next time?" (Blocks, Tiles, Don't mind, Skip). Focus goes to the first. **Done**, or closing, logs any question left as skipped.
  - **For browser tests:** the development server switches study mode on with `window.__storystageStudy = true` (`devPrompter.ts`), never in a release build.

### 2.2 Themes

The design system has **one set of tokens, named by role** (`stage-0`, `panel-2`, `chalk`, `amber`, `prompter`, `ok`, `flag` and the rest; Direction A's README lists them). Components use only tokens, never a colour value. A theme is a set of values for those tokens.

- **Dark** is the default theme and the one approved with Direction A.
- **Light** (decision 0032) was approved on 25 Oct 2026 ([0038](../decisions/0038-light-theme-approved.md)); its values are in the token files and the handoff README ("Colour, light theme").
- **Settings › Accessibility › Theme** offers Dark, Light, or Match this device (`prefers-color-scheme`). The default is Dark ([0037](../decisions/0037-theme-setting.md)).
- **Forced colours** (Windows contrast themes): the components give way to the system colours, keep their outlines and focus rings, and never hide state behind a background colour alone.
- **Reduced motion** (`prefers-reduced-motion`): no animated transitions in the shell. The 3D scene and the film still play.

### 2.3 Frame status

A frame moves through **Planned** (it has a storyboard frame), **Staged** (actors are placed), **Coded** (its program isn't empty), **Rehearsed** (played since its last change) and **Checked** (passes the automatic check, or its flags have been kept). **Look at** marks a frame with an open flag. Editing a frame's code moves it back to Coded. A status always shows its icon and its word, never colour alone (Direction A's status colours).

As built (10 Nov): **Staged** when the scene's set-up has something in it and every character the frame sketches (a model on the scene card's cast, as the check counts characters) is a set-up object; **Coded** when the frame links to a block still in the program; **Rehearsed** when a Rehearse run since the frame last changed started one of its linked blocks (the driver's `ran` trace), or, for a frame with no links, reached the scene's end. "Changed" is the automatic check's `basis` (spec 08 section 9.6): the program, the scene's set-up, the frame and its neighbours, and its pinned lines. Rehearsed lasts for the session; it isn't saved in the film. **Checked** and **Look at** come from the check's saved result while it isn't stale, and win over the rest.

### 2.4 The Prompter panel

What the panel shows (from StoryStage 1 spec 04 §3, plus plan before change, 13.9):

| State | Shown | Controls |
|---|---|---|
| Not in this build | Nothing: no panel, no rail; the neutral note from 12b where the panel would be | none |
| Off for this class | The neutral note from 12a, "switched off by your school" | none |
| Not set up | "Ask an adult to set up the Prompter." | none for learners; adults see **Set up…** |
| Ready | "You asked" bubbles so far, or a greeting | Type or say a request |

### 2.5 Notes, unavailable controls and saving

- **Neutral note** (Direction A component): for something switched off or not available here. It is never styled as an error.
- **Unavailable controls** say why, in a visible line or a tip, not only by looking grey (for example Rehearse on screen 02c, "Nothing on the stage yet").
- **Saving:** changes save themselves. The page says "All changes saved" when they have. The browser version shows a banner while work isn't saved to a file (8.4).

### 2.6 Where the design system lives

A new package, **`packages/ui`** (`@storystage/ui`, owned by S5), holds the tokens (as CSS custom properties and as TypeScript), the bundled fonts and icons (decision 0031), the components (12.3, on React Aria Components, Apache-2.0) and the strings helper. It depends on React and React Aria only, and on no other workspace package. `apps/studio`, `packages/blocks`, `packages/tiles`, the frame canvas in `packages/sketches` and the Screening room use it. It can't live in `apps/studio`, because nothing may depend on the studio. Workplan section 4 doesn't list it yet.

## 3. Words

The rules are `CLAUDE.md` rule 9 and Direction A's "Hard rules".

- **The learner's view:** "the cat", "your scene", "the move block". These words never appear on screen: AST, node, field, invocation, token, schema, API, and "edit" as a noun (a change is "a change", not "an edit"). "Edit" as a button that edits is fine.
- **Product terms, used exactly** (12.4): Storyboard, Production stage, Screening room, Backstage (Cast, Props, Set, Backdrops), Rehearse, Code editor (Blocks or Tiles), the Prompter, frame, shot, Export for distribution, Projection stage.
- **Steps are named after what changed:** "Add cat", "Make cat say Hello". These are also the undo labels (WP2.3).
- **Errors say what happened and what to do next,** with no apologies.
- **Style:** UK English; short and encouraging; no exclamation-mark overload.
- **Strings live in translation files** (12.4), never in components: one file per package and language, `src/strings/en-GB.json`, with keys named by place (`storyboard.shot.medium`). Text can carry named values (`{name}`); plurals use the language's plural rules (`Intl.PluralRules`). The first release ships English (UK) only; the files let Welsh, Scottish Gaelic or Irish follow after the pilot ([0036](../decisions/0036-languages.md)).

## 4. Accessibility

WCAG 2.2 AA throughout (rule 7), with these specifics:

- **Contrast:** text 4.5:1 (3:1 for large text); outlines and focus rings 3:1, in both themes. Status never by colour alone.
- **Focus:** every interactive element shows Direction A's focus ring, a 2 px gap in the surface's colour, then 3 px of amber (a dark-amber ring on light surfaces, a chalk ring on amber ones). Focus is never hidden under a panel or the on-screen keyboard (2.4.11).
- **Targets:** 44 × 44 px or larger, beyond the 24 px the standard asks (2.5.8).
- **Dragging:** every drag has a single-pointer and a keyboard alternative ("Move to…", arrow keys while focused) (2.5.7).
- **Keyboard paths:** every task in all three tabs can be done from the keyboard alone (the M4 manual test). Regions are landmarks: the header (banner), the mode tabs (tab list), the working area (main), Backstage, the script pane and the Prompter (complementary, each named). Keyboard shortcuts live in one keymap, avoid keys the browser reserves, and are listed under Learn. The keymap lands with the first shortcut: the shell needs none, because Tab and the arrow keys reach every part of it.
- **Screen readers:** each component has a role and an accessible name (React Aria provides most). Changes the learner didn't make themselves are announced in a polite live region: the Prompter's state, build and export progress, and the automatic check's results.
- **Speech:** captions for all speech, always (rule 7). Every mic button has a typed alternative beside it, except the key field, where speaking isn't offered at all.
- **Zoom and text size:** decision 0033 sets the working tabs' minimum at 1024 px wide. At 200% zoom a 1366 px window is only 683 px wide, so:
  - the three working tabs (the stage, the editors, the frame canvas) count as content that needs two-dimensional layout (the exception in 1.4.10), and below 1024 px they show 0033's note;
  - Settings, Learn, the set-up wizard and every dialog reflow down to 320 px and never show the note;

## 6. The Storyboard (WP10a)

Direction A's screen 01, at the sizes in section 1. The data is `03-production-format.md` sections 3–6; this section is what the learner sees and does with it.

### 6.1 Layout

Left to right: **Backstage** (the Cast, Props, Set and Backdrops this production uses; the whole catalogue joins with 10.9), the **sketch library** (sketches of those items, then the storyboard marks and the backdrop sketches), the **main area** (script header, scene strip, frame tools, frame canvas) and the **script pane**. On iPad, Backstage folds to its rail (section 1.2). Each column is a named landmark (section 4).

Until Backstage's catalogue loads at run time (WP3c, S4), the sketch library offers the storyboard marks, the backdrop sketches and labelled stand-ins.

As built (15 Nov; WP10.9): Backstage is the Production stage's rail of Cast, Props, Set and Backdrops, beside the sketch library, its panel over the library, searching the whole catalogue. **Add** puts a model in the current scene's cast as one undo step ("Add Knight to scene 1's cast"), and its sketch joins Sketches; a backdrop puts its sketch on the current frame. Under the items, **Can't find it?**: "What is it?" and **Stand it in for scene N** add a labelled stand-in to the cast, and a line says where importing is when the school's policy lets learners (Settings › Class models) or the teacher ("ask your teacher") import.

### 6.2 Script header (10.1)

- **Title**, **logline** (one sentence) and **synopsis** (a short paragraph), each a text field with its mic button once speech is in (WP14). The Prompter never writes them (rule 4).
- Until the logline and the synopsis both have words in them, **Add a scene** is unavailable and says why: "Write a logline and a synopsis first."
- A "3 scenes · 1 min 12 s" pill sums the scenes and the frames' planned lengths.

### 6.3 Arc (10.2)

- The learner picks **Free**, **3-part** (Beginning, Middle, End) or **5-part** (Setup, Conflict, Challenge, Climax, Resolution). Free has no parts.
- A template is an id, a name and its part names, in one list (`ARC_TEMPLATES`). A curriculum template (WP16) joins the list by id (`{ curriculum: '<id>' }` in the data), with no code change.
- Each scene card can belong to one part. Changing the template keeps a card's part only if the new template has a part of that name, and is one undo step ("Change arc to 5-part").

### 6.4 Scenes and frames (10.3)

- **Scene cards** show their number and heading (place and time, "Forest, night"), arc part, cast, transition (cut, fade to black, crossfade) and length. A card's heading is what 10.8's storyboard rule checks. The chosen scene's card is shown in full below the strip: its heading, part of the arc (or none), how it ends (the last scene's ending isn't used, and says so), its cast, and **Delete scene**. The cast is filled from Backstage (10.9).
- **Add a scene** adds a card, its code and its set-up as one step (`packages/production`, through a contract PR S4 reviews). **Delete** asks first, saying what goes with it (its frames, its lines and its code); it's one undo step.
- **Reorder** scenes by dragging a card's handle, or from the keyboard: focus the handle, Enter, the arrow keys, Enter. This reorders the running order (03 section 3). Frames reorder within their scene the same way.
- **Frames** sit under their card as numbered squares (2.1, 2.2). Choosing one makes it the current frame, which stays current across the three tabs. **Add a frame** adds one after the current frame. Deleting a frame with sketches or pinned lines asks first; its lines stay in the script, unpinned.
- "Most scenes need 3 to 9 frames" shows as a hint beside a scene with fewer or more. It never blocks anything.

### 6.5 Frame canvas (10.6)

- A white 16:9 frame with black-line sketches on it (decision 0014: no outside drawings), its caption, **shot** and **length** above it, and its pinned lines below it.
- **Shot:** Wide, Medium and Close-up in the segmented control (Direction A); Over the shoulder, Two shot and Follow under **More shots**. **Length:** a stepper from 1 to 30 seconds, 3 by default.
- **Adding a sketch:** drag it from the library (by the tile, or by its handle from the keyboard), or focus it and press Enter, which puts it in the middle of the frame, in front, and chooses it. Its facing and pose (front, three-quarter, side, back; standing, walking, pointing, sitting) are chosen in the library once Backstage's catalogue gives models their sketches (WP3c); marks, backdrop sketches and stand-ins have none. As built (15 Nov; WP10.9): **Facing** and **Pose** above Cast and props, each a 2 by 2 choice, shown while a model in the cast has sketches (Pose only with the poses the cast has); the tiles are drawn that way, and a model goes on the frame that way, by Enter or by drag, keeping it on the frame, in the print and in Compare. A pose a model wasn't drawn in is drawn standing. A frame holds up to 30 sketches; at 30 the library says so and adds no more.
- **The selected sketch** has an amber box with corner handles (edged in ink, so it shows on the white), and a toolbar of labelled buttons below the frame: **Flip**, **Bring forward**, **Send back**, **Bigger**, **Smaller** and **Remove**. Drag a sketch to move it; drag a corner handle to resize it.
- **Every drag has a keyboard way** (section 4), the same way as reordering scenes: pick up, move, put down. The sketches on a frame are a list, back to front, that the arrow keys move through ("Owl, on the left"); Home and End go to the ends. **Enter** (or Space) picks the focused sketch up; then the arrow keys move it 1% of the frame (10% with Shift), and + and − scale it by 10% (from 0.1 to 3 times), until **Enter**, Space or Esc puts it down, saying where it is. **Delete** removes the focused sketch. These keys work only while a sketch has focus (WCAG 2.1.4).
- Each change is one undo step, named for what changed: "Move owl", "Flip cat", "Remove key". One pick-up's moves are one step, as are one drag's; its resizes are another.

### 6.6 Script pane (10.4)

- **Script · Scene 2** lists the scene's lines in order. **Action** lines are paragraphs; **dialogue** lines carry the speaker's name in capitals, then the line.
- **Adding a line:** the "Type or say a line…" field (Enter or **Add line** adds it at the end of the scene), with **Who says it** above it: Action, the scene's cast, anyone already speaking in the script, or a name the learner types. Its list opens from its button or as the learner types, never just on focus. Who says it stays as it was for the next line.
- **Changing a line:** choosing a line opens it below the list, like the chosen scene card: its words, **Who says line 3**, and **Delete line** (one undo step, no question). Typing into a line is one undo step until the learner leaves it. A line is stored as the script file keeps it (`scriptLineText`, `03-production-format.md` section 5: no blank lines, no spaces at the ends): a new line when it's added, and a changed one when the learner leaves it, in the same step, so the script reopens exactly.
- **Pinning:** each line has a **Pin** button, showing the frame's number once pinned. It offers the current frame first ("Pin to frame 2.3, this frame"), then the scene's other frames, and **Unpin** when the line is pinned. With no frames in the scene the button is unavailable and the pane says to add one. Lines pinned to the current frame are highlighted, and show under the frame canvas. A line can be pinned to one frame; a frame can have several lines.
- Lines reorder by their handle, by drag and by keyboard, as cards do. A line holds up to 500 characters, a speaker's name 40, and the script 2,000 lines.
- **Fountain:** reading and writing follow 03 section 5, with its size limits, in `packages/production` (a contract PR S4 reviews). **Import a script** and **Export the script** appear when the host can open and save files (WP8.4). Importing is offered only while the production has no scenes yet: each heading becomes a scene, with its lines under it. As built (15 Nov; WP10.4): **Import a script** sits under Add a scene and, like it, waits for the logline and synopsis; it takes a `.fountain` or `.txt` file, and the scenes and lines come in as one undo step ("Import the script"), scene 1 open. The film keeps its own title, logline and synopsis; ids and pins in the file are left out, as the new scenes have no frames yet. A file over the limits, or one that isn't text, isn't opened, and the note under the button says why ("That script has more than 50 scenes, so it can't be opened."). **Export the script**, beside Print storyboard once there is a scene, saves `writeFountain`'s file through the host's picker, named for the film ("The Lost Penguin.fountain").

### 6.7 Print (10.7)

**Print storyboard**, beside Undo and Redo, opens a print layout in the device's print dialog, which also offers Save as PDF (decision 0054). The layout is in the page only while the dialog is open, and the app itself never prints. It is black on white in either theme, A4 landscape:

- the title, logline and synopsis;
- then each scene in running order: its number, heading and arc part, and its frames three to a row, each with its sketches, shot, length, caption and pinned lines, and a ruled line under it for the teacher's marks;
- the production's title and the page number at the foot of every page (CSS `@page` margin boxes).

A frame is never split across two pages. Where a device's web view can't print (to be checked in the desktop shells and on iPad), the host gives it a native print step, with the same layout.

### 6.8 Undo

The studio keeps one undo history, the production's own session (`ProductionSession`, WP8.2, S4), which the Storyboard, the Code editor and the stage share: Ctrl+Z (Cmd+Z on a Mac and iPad) undoes, and Ctrl+Shift+Z (Cmd+Shift+Z) redoes. These are the first shortcuts in the keymap (section 4), and Learn lists them. In a text field they belong to the field, which undoes its own typing. **Undo** and **Redo** buttons above the script header do the same for touch and the mouse; each is named for the step it would undo ("Undo: Write logline"), and a screen reader hears what was undone. Typing into one field is one step until the learner leaves the field. Every step is named after what changed: "Write logline", "Add scene 3", "Move cat". Adding, deleting and moving scenes are the session's scene steps, so a scene's code, set-up and card undo together.

### 7.2 Scene view (7.1)

- **What it shows:** the current scene's set-up on the stage (`@storystage/stage`). **Camera view** looks through the scene's camera, as the film will. **Look around** orbits a separate camera with the pointer, touch or arrow keys, and never changes the scene. "In this shot:" names what the scene's camera sees.
- **Moving the view (owner, 24 Nov):** the view circles left or right round what it looks at, tilts (rises and looks down, or drops and looks up), zooms in and out, and pans left, right, up and down, by the buttons below, the keys, the pointer or touch. The stage gives each step (`ViewStep`): `viewStep` moves Look around's camera, and `steppedCamera` says where the scene's camera would go, round the same point Look around turns round: as far ahead as what's in the shot, or where the line of sight meets the ground, or 8 m ahead. A step is its key's size: a 24th of a turn, 1.25 times nearer or further, or a sixth of the way to that point. Panning slides without turning, so the scene moves the other way in the picture. Keys, while the view has focus: the arrows circle and tilt, Shift and the arrows pan, + and − zoom. Pointer: a drag circles and tilts, a Shift-drag or a right-drag pans, the wheel zooms. Touch: one finger circles and tilts; two fingers pan as they move together and zoom as they pinch.
- **The buttons for it** (the owner, 24 Nov 2026, through S2; the keys, a drag, the wheel and a pinch aren't found by most learners, and there was no way to slide the view): under the view, a **Move the view** toolbar of icon buttons in four groups, each named in plain words as its accessible name and tooltip, and each repeating while held, as a held key does:
  - **Slide:** left, up, down and right, the view moving without turning (S3's pan, a new step for the stage);
  - **Circle round:** to the left and to the right, as ← and →;
  - **Tilt:** **Rise and look down**, and **Drop and look up**, as ↑ and ↓;
  - **Zoom:** in and out, as + and −.
  They're 44 px, for a tablet, and under the view, so they never cover a handle or "In this shot:". In **Look around** they move its own view and never change the scene. In **Camera view** (the owner's choice, 24 Nov) they move the scene's camera, live while held, and each press or hold is one undo step, named for what it did ("Circle the camera round to the left"). They call the stage's `viewStep`, or in Camera view write `steppedCamera`'s answer with `setObject`. The buttons are off while a run is on, as Look around is, and in Camera view for a film that can't be changed.
- **Adding:** drag a model from Backstage onto the stage, or focus it and press Enter, which puts it on the ground in front of the camera, facing it. A new object is a field in the scene's type and an entry in its set-up, as one undo step ("Add owl"), through the production's edits (`add_model`, WP8.2, S4).
- **Choosing an object:** click or tap it, or choose it in **Objects in this scene**, a list beside the view that is its keyboard path (as the sketches are on a frame, section 6.5). The chosen object has an amber outline and handles to move it along the ground (up and down with Shift), turn it and resize it, and a row of fields: x, y and z in metres, the turn in turns (Alice's unit, `02-story-api.md` section 1) and the size.
- **From the keyboard:** in the list, Enter picks the object up; then the arrow keys move it 10 cm (1 m with Shift), Page Up and Page Down raise and lower it, [ and ] turn it an eighth, + and − resize it by 10%, and Enter or Esc puts it down, saying where it is. One pick-up is one undo step, as one drag is.
- **Posing:** a character's **Pose** lists its joints from the joint map (WP3.3); each turns by fields or handles (decision 0051: joints turn only). The joint map gives no limits, so each field turns a joint at most half a turn either way (tilt a quarter, as it reads back). **Drag posing** (decision 0073): the hands and feet have handles on the stage, and dragging one bends the arm or leg so it follows, by inverse kinematics; joints still only turn, the shoulder or hip stays put, an elbow bends out and back and a knee forwards. One drag is one undo step; Esc puts it back. As built in the stage (26 Nov, S3, the API agreed with S5): `EditableStage.poseHandles`, `poseHandleJoints`, `showPoseHandles`, `onPose`, `cancelDrag` (true if there was a drag), a tap reported with `Picked.pose`, and for the keyboard `handlePlace` and `posedReaching`. Each handle is an amber ball edged in ink with a 44 px target; while posing the object keeps its outline and its own handles hide. The Pose panel's side is S5's (7.16).
- **Camera and markers:** **Move the camera here** (from Look around) sets the scene's camera to the view, as one step; **Add a marker** puts a camera or object marker where the view is. Markers are objects in the list.
- **Removing:** **Remove** on the chosen object, which asks first when the code uses it, saying where, and is refused in plain words while code still needs it (as deleting a scene is, `03-production-format.md` section 2).
- **What the stage needs to add** (a contract request to S3, `00-architecture.md` section 6): the object at a point on the view (picking for editing, not only for running); an outline and handles drawn on the chosen object; a Look around camera that leaves the set-up alone; changing one object's transform or joint in the loaded set-up without reloading; and which objects the scene's camera sees.
- **Set the stage from the storyboard, as built (15 Nov; WP10.10):** offered once a session for each scene whose storyboard shows something its stage doesn't have, over the scene view, listing it by section with Place everything, Choose what to place (a check box each) and Not now; **Set up from storyboard** stays under the view. Frame N.1 sets the places: a sketch's side of the frame is the picture's side, its height on the frame how near the camera it stands (no nearer than a wide shot allows, no further than a close-up does), and its view and flip which way it faces, as the automatic check reads them (spec 08 section 9.2). Cast first sketched in a later frame wait just off the picture's edge on the side they come in from, facing in. A backdrop sketch chooses, for each part, the first Backstage backdrop whose sketch it is; the scene's heading chooses a part that neither a sketch nor the stage has ("Forest, night": Dark forest floor and Night), listed as "…, from the scene's heading". When something already on the stage would break frame N.1's shot, a **Camera** item moves it: "Closer to Knight, for the close-up", along the line Knight is seen on, or "Further back, for the wide shot"; left out, everything is placed for the camera where it is. One undo step. Cast the storyboard gains afterwards bring the offer back, for them alone: "Add the new cast from your storyboard?"
- **As built (14 Nov), on S3's `EditableStage` (#387, #394):** while nothing runs the stage is in edit mode. A click on an object chooses it, on the stage and in Objects in this scene alike, and a click on the ground chooses nothing; choosing in the list gives the stage's outline and handles. A handle drag moves the object live and is written when it's let go, as one undo step named for what it did ("Move penguin", "Turn penguin", "Resize penguin"); the camera's and a marker's are written too. Under the view, **Camera view** and **Look around**, with **Move the camera here** while looking around (one step, "Move the camera"), and "In this shot:" naming what the scene's camera sees, asked again each time the set-up is shown. A model dragged from Backstage's panel onto the view lands where it's dropped, on the ground under the pointer, facing the camera, and is chosen; each item has a drag button for the keyboard. Rehearse turns edit mode and Look around off, and Look around can't be chosen while a run is on; the row stays, so nothing below moves. A film that can't be changed has no handles and no Move the camera here. As built (15 Nov): the keyboard pick-up in the list, by the keys above. The arrow keys move the object as the scene's camera sees it, Up away from the camera and Right to its right, and the fields' limits hold. The held object is ringed in amber in the list, and focus stays on it. A pick-up is said ("Picked up penguin. Arrow keys move it…") and so is where it was put down ("Put down penguin at x -2.7, y 0, z 0 metres, turned 0.75, size 1."). Leaving the list puts it down too. One pick-up is one undo step, named for what its first key did ("Move penguin"). As built (15 Nov), on S3's `SceneObjectSetup.joints` (#424) and S4's 1.5.0 (#429): **Pose knight** under the chosen object's fields, for a Backstage model whose class has joints (not a prop or a stand-in). **Joint** lists every joint the model has, by its word on the blocks: the joint map's first, in its order (Pelvis, Spine base, … Head, Left shoulder, Left elbow…), then the model's own ("Plumage center tip"); a posed one says "posed". Its turn from rest shows as **Heading**, **Tilt** and **Roll**, in turns, about the joint's own y, then x, then z, read back the same way (S3), so a pose shows the numbers typed. Typing poses the character on the stage, one undo step for each run of typing ("Pose knight's head"); **Straighten** puts the joint back at rest ("Straighten knight's head"). A joint at rest isn't written, and nor is `joints` when none is posed. As built (16 Nov): **Add a marker here**, under the view while editing, puts a marker where the view is, Look around's or, in Camera view, the scene camera's, with its turn (a camera marker), named `marker1`, `marker2`… as the first free, as one undo step ("Add marker1"); it is chosen, with the stage's handles, and said ("marker1 is where the view is, in Objects in this scene."). As built (26 Nov), on S3's WP5d (#698): **Pose on the stage**, a switch at the top of Pose for a character the stage can pose by a hand or a foot (one whose arm or leg has all three joints; not a prop or a stand-in), shows its hands and feet on the stage, and the character keeps its outline while its move, turn and resize handles hide; switched off, or with something else chosen, they come back. ### 7.3 Code editor (7.2, 7.6)

- **Closed until the scene is storyboarded** (section 1.4).
- **One method per tab:** the scene's script method first, then its listeners ("When the scene starts", "When the cat is clicked"), then the learner's procedures and functions. **New** adds a procedure, a function or an event listener to the scene or to a class of the learner's.
- **The palette** (300 px): an object picker (the scene, its camera, its objects, and the object a method belongs to), then that object's Actions and Questions in Alice's categories (`14-editors.md` section 2.1), and the control blocks: do in order, do together, count, while, for each, each in together, if, a variable, assign, comment and return.
- **Adding a block:** drag it into the method, or focus it in the palette and press Enter, which puts it after the statement with focus (or at the end of the method). **The timeline**

### 8.2 A starting lock for a class

What the teacher's guide suggests a pilot school sets first, in the policy file's format (spec 05 §3.5). Some lines only say the default out loud, so the school can see it; nothing here turns anything on for a learner, and the Prompter stays off until an adult adds a key (0022).

```
prompter.enabled=true
prompter.dailyCap=20
prompter.capAction=explainOnly
backstage.import=teacher
backstage.search=false
editor.locked=false
update.channel=pilot
```

A pilot school is on the `pilot` channel (spec 05 §4.4); other schools use `stable`. During a term, add `update.pin=<version>` to hold the class on one build. For an exam or an unsupervised room, `prompter.enabled=false`.

### 8.4 Questions for the pilot teacher

Until they're answered, §9 takes the simplest choice for each, so an answer changes one small piece rather than the screens' shape: Import class list is pasting a list, one name a line; there's no PIN; and a folder closes when the app closes or the pupil chooses Switch pupil.

- **Adding 30 names one at a time is slow.** Would pasting a list, or reading a CSV from the school's system, help? (The target is a class set up in under 15 minutes.)
- **Teacher-only screens have no password.** The bin, promoting a pupil's model and the usage view are behind Settings, on the trust model of the name picker (PS1). Is that enough in a classroom, or does the teacher need a PIN?
- **Ending the lesson:** should the folder close when the app closes, after a time with nothing done, or only when the teacher says so?
- **Marking:** marks go on the printed storyboard or into the school's own system. StoryStage has no teacher comments inside a production. Is that a gap?
- **The same device each lesson:** if pupils rarely get it, Collect and Hand back become every lesson's routine, and the guide should say so first.

## 9. Save and open (WP8.4 in the studio)

A pupil's films live in their own folder on the device ([0065](../decisions/0065-pupil-work-between-lessons.md)), saved by S4's `ProductionSaver` through the host's pupil folders (`HostInterface.classes`, spec 05 section 6), and move between devices as files through the system's own picker (`HostInterface.picker`). The teacher's side of the same lesson is section 8. The owner settled three choices on 8 Nov 2026: a full-screen name page, one folder and no name page without a class list, and a Film menu on the production's title.

### 9.1 The start of a lesson

- **The name page.** When the class list has names, the studio opens on "Who's making films today?": every pupil's name as a large button (44 px or more, with their picture if they have one), in alphabetical order, with a search (and its mic) above them, and "Not on the list? Ask your teacher." below. Choosing a name opens that pupil's folder (`classes.open`); nothing else is shown until then. A quiet **Settings** button in the page's corner is the teacher's way to Class set-up (9.4) before anyone's folder is open, on the same trust as the bin (PS1; the owner's choice, 8 Nov); **Back to the names** reads the class again.
- **No class list** (at home, or a club that hasn't added names): StoryStage keeps one folder for the device (`ClassFolders.openDevice`), opens it straight away, and never shows the name page. Adding pupils in Settings turns the name page on for next time; the device's earlier films stay safe and move to a pupil from Settings (9.4).
- **My films.** Once a folder is open: the pupil's films as cards, newest first, each with its title, a sketch of its first frame and "Saved 10 minutes ago", and **New film** first. Choosing a film opens it (`openFromFolder`); New film starts an empty production. A pupil with no films yet goes straight to a new one.
- **Opening a film** follows `openProduction`'s answer:
    - **ok:** it opens, in the Storyboard, at its first scene;
    - **migrated** (made in an older StoryStage): it opens, and a neutral note says "This film was updated to work in this version. The original is kept." The saver keeps the original;
    - **readOnly** (made in a newer StoryStage): it opens to watch and read, nothing can change, and the note says why and offers **Save a copy**;
    - **broken** or **unavailable:** it doesn't open. The page says what happened in S4's plain words and offers the film's backups (`backups`, up to five, each with when it was saved), newest first.
- **The header** shows the pupil's name after the production's title ("The Owl and the Key · Ada K."), so whose folder is open is always visible.

### 9.2 Saving

- **Autosave.** Every change is saved by itself (`save(…, 'auto')`), a moment after the learner stops, when they change tab, and before the folder closes. The header's status says "Saving…", then "Saved", in the polite live region, and never interrupts.
- **Save now:** Ctrl+S (Cmd+S) saves straight away (`'asked'`), which also marks a backup point. There's no Save button: autosave is the rule, as on screen 11's "All changes saved".
- **Class models travel with the film.** Every save, and Save a copy, first packs the class-imported models the film uses (`packModels`, decision 0049), so the film opens on any device. A model packed on an earlier save stays in the film, even after the class Backstage loses it (spec 03, section 1.3). A model the film uses that this device's class Backstage doesn't have, and the film doesn't yet carry, can't be packed; the film still saves, and a neutral note names it: "This film uses imported models this device doesn't have: big robot, crate. They're shown as outlines, and the film still saves." (up to three names, then "and 2 more").
- **When a save fails,** the status turns into S4's plain words ("There's no room left on this device to save your film. Ask your teacher.") with **Try again**, and stays until a save works. The learner's work stays in the studio meanwhile.
- **Leaving with work not yet saved** (closing the window or the browser tab while a save is waiting or has failed) asks first: the browser's own "Leave site?" question in the browser version, the app's own dialog in the desktop apps.
- **The browser version** says once, the first time a folder opens there, as a neutral note: "Your films are kept in this browser on this device. Use Save a copy to keep one somewhere else." When the browser hasn't agreed to keep pupils' files (`HostInterface.storagePersistent`, #272), the note adds "This browser may clear your films if space runs low, so use Save a copy to keep the ones that matter." Nothing waits for that answer (Firefox gives it only once the person answers its own prompt): the warning joins the note when it comes.

### 9.3 The Film menu

The production's title in the header is a button that opens the **Film** menu:

- **New film:** saves this one, then starts an empty production in the same folder.
- **My films:** saves this one, then the film list (9.1).
- **Open a copy…:** the system's open picker (`openFromPicker`). The film opens as a new film in the pupil's folder, so the file picked is never changed. A file StoryStage can't open is refused in plain words before anything changes.
- **Open an Alice world…** (WP9, spec 19): picks an `.a3p`, imported by S6's `importAliceInWorker` in a fresh worker, stopped after 60 seconds (spec 15, section 3). A file that isn't a world is refused in S6's plain words, and nothing changes. Otherwise this film is saved, and the world opens as a new film in the pupil's folder, saved at once so it's in My films (`manifest.origin: 'alice'`). Then a dialog lists what didn't come across, grouped by kind with the count of each (models, set-up, classes, blocks, values, events and other), each with what it was in Alice, where and why; a world with no gaps says so in one line. **Start working** closes it. Until the studio has the shipped Backstage, every Alice model comes in as a labelled stand-in at Alice's size, and the report says so.
- **Save a copy…:** the system's save picker (`saveCopy`), named after the title ("The Owl and the Key.storystage"). Closing the picker saves nothing and says nothing.
- **Switch pupil** (with a class list): saves, closes the folder (`classes.close`) and goes back to the name page.

A folder also closes when the app closes. Whether it should close after a time with nothing done waits for the pilot teacher (section 8.4).

### 9.4 Settings › Class set-up (screen 11)

When the browser hasn't agreed to keep pupils' files, the same warning as in 9.2 sits under the page's title, without the page waiting for the answer.

**Pupils and folders**, as drawn:

- **The list:** each pupil with a folder icon, their name, how many films they have, and a chevron that opens their folder: their films, each with **Move to the bin**. A search filters the list.
- **Add pupil:** a name (up to 40 characters), not already in the class (ignoring case and spaces). A picture from a small set comes once the set is drawn; names only for now (the owner's choice, 8 Nov). **Rename** and **Remove** are on the pupil's own page. Removing a pupil asks first and says how many films go to the bin with them; the pupil whose folder is open in the studio can't be removed, nor the film that is open moved to the bin. Removing is undone from the bin: **Restore {name}** puts the pupil back with the same folder (S8's `restorePupil`, #262) and brings their films back with them.
- **Import class list:** paste names, one a line; the list shows what will be added, with any name already there, or too long, marked and left out. Reading a file from the school's system waits for the pilot teacher (section 8.4).
- **The bin:** films and pupils removed, newest first, each film with whose it was and when it was moved, which only the teacher sees (PS1), with **Restore** and **Empty the bin** (which asks first, says how many films go, and can't be undone). Removed pupils are listed first, each with **Restore**, which puts the pupil back and brings their films back with them; a removed pupil's film can't be restored on its own until then.
- **Films kept from before the class list:** a device used without names keeps its films in its own folder (`openDevice`, spec 05 section 6.2), which no pupil can open once the class has names. When that folder has films and the class has names, Pupils and folders lists them, with **Move these films to…** a pupil, which moves them all at once (S8's `deviceFilms` and `moveDeviceFilms`, #259). It's off while the device's folder is open in the studio. The name page never offers the device's folder.

**Collect and Hand back**, on the same page under the list:

- **Collect** asks the system's picker for a folder and writes one folder per pupil into it (`collectClass`), then says how many films it collected. Nothing is written if any name would clash, and the page says so.
- **Hand back** asks for that folder and returns each file to its pupil (`handBackClass`); the page then lists what came back, and each file it skipped with S4's reason in plain words.

**The Prompter's use today** (24.5, `HostInterface.prompterUsage`) has a panel of its own on this page: each pupil's requests today against the daily limit, "this device" for requests with no folder open, and "a pupil no longer in the class" for a pupil since removed.

**Study, as built (17 Nov; spec 14 sections 6.1, 6.2, 6.7 and 6.8; WP7.13):** shown only while study mode is on, which needs a policy from a trusted source with `study.enabled`.
- **The tick:** each pupil in Pupils and folders has a tick, **Taking part in the study: Ava**, with "Tick each pupil taking part in the study." above the list.
  - The tick is its own control in the row, so pressing the row still opens the pupil's page. The arrow keys reach it.
  - The ticks are kept in the study's own store, never in a pupil's folder.
  - Removing a pupil takes their tick away.
- **The Study card** appears while study mode is on, and also while any logs are kept, which stay the teacher's to export or delete.
  - **Study class code**, at most 12 letters, digits and dashes, says when one won't do. **Age band** offers 6–8, 9–11 or 12–13, and **Save** keeps both.
  - **Sessions on this device** lists each session's code ("Session K7P3-QX2M"), its date and how many tasks it did. **Delete** asks first and can't be undone.
  - **Export study logs** saves one file through the system's picker. It then asks **Delete these logs from this device?**, with **Delete from this device** and **Keep for now**.
- **The store:** S8's `host.classes.study()` (#491), the class store's `study` folder beside the pupils' folders. Every host has one; study mode stays off in the browser version because its policy is never from a trusted source.

### 9.5 Keyboard and names

The name page's names are a grid of buttons the arrow keys move through; the film list is too. The Film menu is a menu: Enter or Space opens it, the arrow keys move, Escape closes it. Every dialog here follows section 4: focus moves into it, stays there, and goes back where it came from.

### 9.6 Class models (WP3.11 and 3.12 in the studio; decision 0066)

The teacher's imports into the class Backstage, on **Settings › Class set-up**, in a **Class models** card under Pupils and folders (the owner's choice, 9 Nov). Learners' own imports come with the Production stage's Backstage rail (WP10c), when the policy's `backstage.import` is `learners`.

- **The card** lists the class Backstage on this device: each model's thumbnail, name, what it is and its credit line, "Stays in school" for CC BY-NC and "not sure", and **Move to the bin**. A pupil's own import says whose it is, with **Make it the class's** (`promote`). **Import a model…** opens the dialog.
- **The import dialog** (Direction A screen 07), details first and then the report (the owner's choice, 9 Nov):
    1. **The details:** the model's files, picked together (a `.glb` or `.vrm`; a `.gltf` with its `.bin` and pictures; an `.obj` with its `.mtl` and pictures), each refused at once if over `FILE_LIMIT`; the name, filled in from the file's name; **What is it?** (a person or character, an animal on four legs, something that flies, swims or slithers, a prop, a vehicle, or part of the set: Backstage's section and class); what it looks like, optional; the licence from spec 17 section 6's short list; where it's from; and who made it, for any CC BY licence (optional for CC0). Nothing runs until the files, the name, the kind and the licence are there.
    2. **Check model** runs S4's import in a fresh worker (`importInWorker`), stopped after 60 seconds. A licence problem comes back before the model is read, in spec 17's words, on the details; so does a refusal of the file.
    3. **The report:** the colour thumbnail and the front sketch the import made (not a live 3D preview, which would load the stage into Settings: the owner's choice, 9 Nov), what Backstage did in plain words, the credit line made from the licence, and the warning when films using it must stay in school. **Add to class models** saves it as the class's; **Change details** goes back a step, and checking again runs the import again.
- **The bin** lists models moved to the bin under their own heading, each with **Restore**; **Empty the bin** empties the class Backstage's bin too, and says how many models go.
- **Save models…** and **Open models…** (the model pack, spec 17 section 5; decision 0066) sit on the Class models card, with the class's own models (decision 0066 put them beside Collect and Hand back; they're with the models they carry). **Save models…** writes the class's own models, not pupils' own imports, to one file through the system's picker (`modelPackFromClass`), named "Class models.storystage-models"; it's off while the class has none. **Open models…** picks a `.storystage-models` file, checks every model as an import in a fresh worker (`openModelPackInWorker`), each with its own 60 seconds, saying "Checking model 3 of 12…" as it goes, then adds those that pass as the class's. It then says how many were added and lists those left out (already in the class, or failing a check), each with S4's reason.
